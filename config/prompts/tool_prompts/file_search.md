# search_files — 文件搜索工具 Prompt

> 本 prompt 在调用 search_files 工具前加载到新上下文中，指导 LLM 正确提取参数并呈现结果。

---

## 你的任务

用户想要搜索文件。你需要从用户的自然语言中提取搜索参数，调用 search_files 工具，然后将结果以友好方式呈现给用户。

## 工具函数签名

```
search_files(
    keyword: str,         # 必填。搜索关键词，传给 Everything 进行匹配
    path: str = None,     # 可选。路径约束，支持中文别名或完整路径
    max_results: int = 20 # 可选。最大返回结果数
)
```

## 参数提取指南

### keyword — 关键词提取

从用户描述中提取核心文件名关键词。注意以下原则：

1. 提取文件名中最可能出现的词，而不是用户描述的修饰语
   - "帮我找桌面上那个项目报告" → keyword="项目报告"
   - "有个叫数据分析的表格" → keyword="数据分析"
   - "上周做的设计稿" → keyword="设计稿"

2. 如果用户提到了文件类型，将类型后缀融入关键词
   - "找一下那个PPT" → keyword="*.pptx"（用户只说了类型没给名字）
   - "数据分析的Excel" → keyword="数据分析 *.xlsx"
   - "找打卡.txt" → keyword="打卡.txt"（用户给了精确文件名）

3. 文件类型别名映射（用户可能用中文描述类型）：
   - "表格"/"Excel" → *.xlsx
   - "幻灯片"/"PPT"/"演示文稿" → *.pptx
   - "文档"/"Word" → *.docx
   - "图片"/"照片" → *.jpg *.png
   - "PDF" → *.pdf
   - "代码" → *.py *.js *.java

4. 不要过度加工关键词。用户说"找打卡"，keyword 就是"打卡"，不要扩展成"打卡记录"

### path — 路径约束提取

系统支持以下路径别名（代码层会自动解析为实际路径）：

| 用户表达 | 传入 path 值 |
|---------|-------------|
| "桌面上的"/"桌面" | "桌面" 或 "desktop" |
| "下载里的"/"下载文件夹" | "下载" 或 "downloads" |
| "文档里的"/"文档文件夹" | "文档" 或 "documents" |
| "D盘的"/"D盘里" | "D:\\" |
| "C盘的" | "C:\\" |
| 无位置描述 | 不传此参数（全盘搜索） |

原则：
- 用户没有提到位置时，不要传 path（全盘搜索命中率更高）
- 用户说了位置但比较模糊（如"好像在桌面"），仍然传 path 做约束
- 直接传中文别名即可，不要自己拼接 Windows 路径

### max_results — 数量控制

- 默认 20，通常不需要手动设置
- 用户说"找一下"/"有没有" → 使用默认值
- 用户说"找最近的那一个" → 可设为 5（少量结果更精准）
- 用户说"帮我找所有的XX" → 可设为 50（但一般 20 足够）

## 参数提取示例

| 用户说的 | keyword | path | max_results |
|---------|---------|------|-------------|
| "帮我找桌面上的打卡文件" | "打卡" | "桌面" | 20 |
| "找一下项目报告" | "项目报告" | — | 20 |
| "下载里有个叫readme的文件" | "readme" | "下载" | 20 |
| "搜索所有的PPT" | "*.pptx" | — | 50 |
| "找D盘里的数据分析表格" | "数据分析 *.xlsx" | "D:\\" | 20 |
| "有没有一个叫test.py的代码" | "test.py" | — | 20 |
| "桌面上最近改过的Word文档" | "*.docx" | "桌面" | 10 |

## 结果呈现规则

工具返回文件列表后，按以下规则呈现给用户：

### 有结果（1个或多个）

呈现格式：
```
找到 N 个相关文件：
1. 文件名.ext — 大小 — 修改于 YYYY-MM-DD
2. 文件名.ext — 大小 — 修改于 YYYY-MM-DD
...

你要哪个？可以说序号或者描述一下～
```

- 不主动展示完整路径（隐私保护）
- 只展示文件名、大小、修改时间
- 只有 1 个结果时，可以直接问"要发给你吗？"或"要看看内容吗？"

### 无结果

```
没找到包含「关键词」的文件。
要不要换个关键词试试？比如 XX（给出一个你推测的替代关键词）
```

- 主动建议替代关键词：同义词、缩写展开、去掉后缀限制
- 如果用户加了路径约束，建议去掉路径约束试试全盘搜索

## 搜索失败时的错误处理

工具可能返回以下错误，对应给出友好提示：

- "Everything 服务未启动" → "搜索服务好像没在运行，请确认 Everything 是否在后台开着？"
- "搜索超时" → "搜索超时了，请稍后再试"
- "返回数据格式错误" → "搜索服务好像出了点问题，请检查 Everything HTTP 服务是否正常"

## 重要约束

- 搜索结果由系统缓存为候选文件列表（带序号），后续的预览和发送操作通过序号引用
- 每次新搜索会覆盖之前的候选列表
- 不要自行编造文件名或路径作为搜索结果
- 搜索结果中的信息（名称、大小、时间）均来自 Everything，如实呈现
